# wxdl GUI v2 设计文档

> 状态：**P0 已完成（2026-10-30）**：CLI `--json` NDJSON 事件流、`status/doctor --json`、
> `--wait-page=forever`，GUI 已改为事件驱动并显示逐条字节进度。P1–P3 未开工。
> 对应当前实现：`gui/`（SwiftUI，v1.1.0）、`main.go` + `internal/flow/`（CLI v1.1.0）。
> 阅读顺序：先看第 1、2 节确认问题和边界，再看第 4 节（CLI 事件流）——它是后面所有界面的前提。

---

## 1. 这份文档要解决什么

把 wxdl 从"有个窗口的命令行"变成"不需要终端的桌面应用"。判定标准只有一条：

> 一个不会用终端的人，从 DMG 装完到把视频拿到手，全程不打开终端、不看 README。

**不解决的（写清楚，避免范围膨胀）：**

- 不做 Windows / Linux。代理与证书那层只有 macOS 实现，见 README「支持范围」。
- 不做登录、云同步、分享页、社区。这是本机工具。
- 不改下载引擎本身的抓取与解密逻辑（`internal/upstream` 与上游引擎），GUI 只调度。
- 不去掉命令行。默认输出、颜色、`\r` 进度、退出码都保持原样；`--json` 是**新增**通道，不是替代。
- 不做"设置项大全"。能自动判断的不让用户选，判断不了才问。

## 2. 现状盘点：v1.1.0 已经有了什么，卡在哪

已有的地基是好的，别推翻：单窗口 SwiftUI、`AppModel` 拉起 `bin/wxdl` 子进程、
`--yes` 走非交互、状态靠 `wxdl status` 轮询、打包链路（DMG/.app）已跑通。
`AppModel.swift` 里对"关窗口先恢复代理再退出"的处理（`shutdown(completion:)`，
12s interrupt → 15s 兜底 terminate）是对的，v2 保留这个行为，只是要把这个过程显式呈现出来。

四个卡点，都能指到具体代码：

### 卡点 A：最容易卡住的一步，GUI 只在启动时说了一次

README 自己写了「**完全退出微信再重开**（第一次最容易卡住的一步）」。
但 GUI 侧的处理是 `AppModel.start()` 里的一句 `notify(.info, ...)`——9 秒后自动消失的横幅，
只在"引擎未安装"时才出现。用户点「开始下载」，真正遇到 `视频号页面未连接` 时：

- **首次运行**：`Prepare()` 在 `--yes` 下等 2 分钟（`internal/flow/flow.go:119`），
  然后整次运行失败，GUI 弹一条 9 秒错误横幅，并会自动追加 Cmd+Q 提示
  （`gui/AppModel.swift:419`、`AppModel.swift:249`）。有提示，但一闪而过，没有可停留的步骤说明。
- **批量中途掉线**：`Batch` 对**每一条**都重新 `reconnect()`；`reconnect()` 的等待是
  45 秒 + 3 分钟 = **3 分 45 秒**（`internal/flow/batch.go:48`、`flow.go:121`）。
  12 条最坏就是 45 分钟，且每条失败都打印「跳过：视频号页面未连接」
  （`batch.go:51`）——这条确实是失败，但文案写着"跳过"，很容易被误解。
- 原稿写的"等满 20 分钟超时退出"不准确：`--timeout` 20 分钟是单个任务的下载等待，
  不用于页面连接。

### 卡点 B：GUI 在抓终端文字，改一个标点就静默失效

`AppModel.handle(line:)` 目前靠字符串匹配推进度：

| 匹配串 | 实际含义 | 现状问题 |
|---|---|---|
| `[1/2]` | 开始一条任务 | 解析格式，改文案就失效 |
| `已保存：` | 成功 | 复用（之前下过）也会走到这里 |
| `已存在，直接复用：` | 已下载复用 | GUI 不认，但随后仍有 `已保存：`，所以当前能显示成功 |
| `跳过：` / `失败：` | 标记失败 | 当前 `跳过：` 只用于页面未连接，本质上就是失败 |
| `❌` | 取错误信息 | 与中文文案耦合 |
| `完成：` | 收尾 | 与中文文案耦合 |

代价有三个：

1. **任何中文文案改动都会让 GUI 静默失效**，而且 GUI 没有测试能发现。
2. **单条字节进度被丢掉。** `下载 16% (4.7MB/28.8MB)` 这行其实是 **wxdl 自己打印的**：
   `progressLine()` 从引擎 `TaskDetail.Files[].Downloaded/Size` 算出来（`internal/flow/flow.go:822`、
   `internal/server/server.go:55`），引擎的 stdout 直接写进 `engine.log`（`server.go:509`），
   GUI 根本收不到。也就是说字节进度**已经是结构化的**，只差在 `waitTask` 里发一个事件，
   不需要解析任何上游文本。原稿把这条列为风险，实际可以直接关闭。
3. **复用没有独立的语义。** 当前 GUI 靠随后那条 `已保存：` 把复用当成功，逻辑上碰巧成立；
   一旦输出顺序或文案变化就会退化。事件流里必须有 `item.skip`，复用不计失败。
4. **日志把 12 万字符塞进一个 `Text`**（`AppModel.swift` 的 `appendLog`），长批次会卡主线程。

原稿里"`progressDone` 用 1 开始的序号，进度会多走一格"**复现不了**：
开始一条时写 `number-1`（`AppModel.swift:491`），完成时写 `number`（`AppModel.swift:466`），
n 条完成就是 n/total。v2 不修这个不存在的问题。

### 卡点 C：常驻模式是个会"留在外面"的状态，现在只有一个胶囊

`wxdl on` 会**退出进程、把代理和引擎留在系统里**（README：「常驻模式是"留在系统里"的」）。
关掉 App 不会恢复网络。当前界面表达这件事的是标题栏右侧的 `StatusPill`（全局可见，
代理指向 wxdl 时显示「常驻中」，`gui/ContentView.swift:68`、`AppModel.swift:565`）
以及「窗口按钮」标签里的一个小标签。

所以原稿说的"切到批量链接就看不见"不准确——**真正的问题是看得见但没有动作、没有详情**：
用户看到「常驻中」却不能一键恢复网络，也看不到已经开了多久。
另外 `wxdl get` 不加 `--keep` 时，跑完会把常驻一并收掉（README:365），
v2 有了底栏和常驻页之后，这个行为会变成"下完一批，常驻突然没了"。

### 卡点 D：`--yes` 把 CLI 的交互全关了，GUI 没有补上

GUI 传 `--yes`（见 `downloadArgs()`），于是这些在终端里有的交互在 App 里全没了：

- 账号昵称不唯一时的**选择弹窗** → 变成直接报错。
  `AccountPane` 里那句「昵称不唯一时不会弹选择框，会直接报错」就是把 CLI 的限制原样告诉用户。
- 批量下载账号前的**确认弹窗**（「准备下载该账号最近 N 个视频，是否继续？」）→ 没了。
  用户手滑填 200 条就直接开始下。

另外一处小的：账号页允许 `limit` 到 200（`ContentView.swift:169`），但 GUI 固定传 `--pages 5`
（`AppModel.swift:276`）；按每页约 20 条算，200 条到不了。v2 要按 `limit` 计算页数或去掉上限。

## 3. 技术路线

| 方案 | 判断 | 理由 |
|---|---|---|
| **A. 继续 SwiftUI 原生** | **选它** | 打包链路已有；提权靠 `internal/elevate`（osascript 原生密码框）在 App 内照样工作；`Process` 调 CLI 的模式已验证；不引入新工具链。 |
| B. Wails / Tauri + 前端 | 不做 | 体积增加、原生感丢失（这不是要跨平台的产品，只有 macOS）；提权那步仍要 osascript，绕不开；现有 GUI 代码全废。 |
| C. Fyne / Gio（Go 自绘） | 不做 | 控件非原生，与"不像 AI 生成、像正经 Mac 应用"的目标相反。 |

结论：**SwiftUI 保留，重写的是信息架构和 CLI 之间的接口，不是技术栈。**
目标系统 macOS 12+（与现 App 一致，打包 target 见 `packaging/package-gui.sh:83`）。
`NavigationSplitView` 是 macOS 13+，侧栏要用 macOS 12 兼容写法（`NavigationView`
或自定义 `HStack`），不因视觉适配上抬最低版本。

## 4. 地基：给 CLI 加机器可读的事件流

**这是全部工作的前提。** 不新增 CLI 输出协议，后面所有界面都只能继续做字符串考古。

### 4.1 形式

新增全局开关 `--json`。规则：

- 不加 `--json`：输出**完全不变**（人读文本、颜色、`\r` 进度），CLI 用户零感知。
- 加 `--json`：`stdout` 只输出 **NDJSON**（一行一个事件，UTF-8，`\n` 结尾），不输出任何装饰字符。
- 面向人的文本降级为 `{"t":"log",...}` 事件，GUI 想显示原文时自己渲染。
- `stderr` 保留给人读的错误兜底；进程退出码语义不变。
- 所有 stdout 输出必须走同一个 emitter；测试逐行解析 stdout，防止以后有人 `fmt.Print` 破坏协议。
- `--json` 不隐含 `--yes`；GUI 两者都传。
- 字节进度由 wxdl 从 `TaskDetail` 直接发 `item.progress`，不再重复打印 `\r` 行；
  引擎进程的 stdout 仍然只进 `engine.log`。
- 新增 `--wait-page=forever`（默认不启用）：页面等不到时不判失败，一直等到用户停止或页面连上。
  GUI 使用它；普通 CLI 的 2 分钟 / 3 分 45 秒超时保持不变。

### 4.2 事件 schema

```jsonc
{"t":"run.start","id":"r-20261030-0712","cmd":"get","total":12,"out":"~/Downloads/wxdl","spec":""}
{"t":"run.plan","total":20}
{"t":"env.check","name":"微信客户端","status":"ok","detail":"正在运行","hint":""}
{"t":"auth.request","reason":"信任 wxdl 本机根证书，并把系统代理临时指向 127.0.0.1:2023"}
{"t":"auth.done","granted":true,"required":true}
{"t":"engine.install","tag":"v260907","phase":"done"}
{"t":"wait.page","timeout":120,"elapsed":5,"connected":false}
{"t":"wait.page","timeout":0,"elapsed":372,"connected":false}
{"t":"wait.page","elapsed":381,"connected":true}
{"t":"item.start","index":1,"total":12,"url":"https://weixin.qq.com/sph/A2oqg1iKx9","title":"…"}
{"t":"item.progress","index":1,"total":12,"pct":16,"bytes":4930212,"total_bytes":30200000,"status":"downloading"}
{"t":"item.done","index":1,"path":"~/Downloads/wxdl/xxx_xWT111.mp4","bytes":30200000,"duration":"2:58","spec":"xWT111"}
{"t":"item.skip","index":2,"reason":"already_downloaded","path":"~/Downloads/wxdl/yyy.mp4"}
{"t":"item.fail","index":3,"code":"page_not_connected","msg":"视频号页面未连接","hint":"Cmd+Q 完全退出微信后重新打开"}
{"t":"item.retry","index":3,"attempt":2}
{"t":"run.progress","done":4,"total":12,"ok":3,"failed":1,"skipped":0}
{"t":"run.done","ok":10,"failed":1,"skipped":1,"dir":"~/Downloads/wxdl","last_file":"…"}
{"t":"log","level":"info","msg":"抓取引擎 v260907 已启动"}
{"t":"error","code":"lock_held","msg":"另一个 wxdl 正在下载","hint":"等它结束，或在那个窗口点停止"}
{"t":"status","download_dir":"…","engine":"…","engine_tag":"v260907","engine_process":"运行中 (pid 123)","engine_running":true,"api":"可访问 (127.0.0.1:2022)","api_alive":true,"service":"Wi-Fi","proxy":"已指向 wxdl (127.0.0.1:2023)","proxy_is_ours":true,"cert":"…","cert_present":true,"cert_trusted":true,"page":"已连接","page_connected":true,"resident":true,"started_at":"2026-10-30T07:12:00Z"}
{"t":"doctor.done","fails":0}
```

约定：

- `code` 是**稳定枚举**，界面靠它选文案和按钮，不靠中文字符串。见第 9 节对照表。
- `skip` 与 `fail` 分开，`already_downloaded` 不当失败；它来自 `downloadOne` 的复用分支，
  不是现有的「跳过：视频号页面未连接」。
- 每个事件带 `index`/`total`，GUI 不需要自己数。
- `run.start.total` 在链接模式下已知；账号模式下先发 0，拉完列表再发 `run.plan.total`。
- `wait.page` 的 `timeout:0` 表示不设上限（`--wait-page=forever`），`connected` 为终态标记。
- 未知 `t` 一律忽略并记录，不允许 GUI 崩溃——这样 CLI 加新事件不会打断老版本 App。
- `error` 的 `msg` 是给人看的短句；路径、退出码、Go error 原文只进 `log`。

### 4.3 要补的子命令

| 命令 | 用途 | 状态 |
|---|---|---|
| `wxdl status --json` | 底栏、菜单栏图标、退出拦截、常驻检测的状态源 | **P0 必须** |
| `wxdl doctor --json` | 诊断页逐项渲染 + 每项修复动作 | **P0 必须**（复用 `flow.Check`） |
| `wxdl accounts <关键词> --json` | 账号搜索结果（昵称、username、头像、视频数） | P2；见下方限制 |

`status --json` 同时提供 `proxy_is_ours`、`resident`、`page_connected`、`cert_trusted` 等布尔值，
GUI 不再解析「抓取引擎进程: 」这类前缀（当前 `applyStatus` 靠前缀匹配 4 个 key，同样脆）。

`accounts` 的限制必须先写清楚：

- 搜索走上游 `search_wxchannels_accounts`，wxdl 现在已经在用它（`flow.go:215`），所以**能力存在**。
- 但它需要引擎、系统代理、根证书和视频号页面，等于一次完整的 `Prepare`。
  如果 `accounts` 独立跑完就恢复代理，紧接着的下载要再授权一次；v2 要么让搜索和下载共用一次
  capture session（例如常驻模式），要么把 6.2 的准备面板复用到账号页。
- 头像 URL、视频数是**未验证字段**；拿不到就不显示，不阻塞账号选择。

## 5. 信息架构

v1 是「批量链接 / 整个账号 / 窗口按钮」三个平级标签。问题在于这三者**不是平级关系**：
前两个是"任务"，第三个是"系统状态"。把状态和功能混在一排，常驻代理就容易被忘掉（卡点 C）。

v2 拆成：**侧栏导航（去哪）+ 底部状态条（现在系统是什么状态）+ 内容区（干活）**。

```
┌─────────────────────────────────────────────────────────────────────┐
│ wxdl                                          [ 环境就绪 ▾ ]  [⚙]   │  统一工具栏
├──────────────┬──────────────────────────────────────────────────────┤
│              │                                                        │
│  下载        │                                                        │
│  账号        │                    内容区                              │
│  已下载      │              （随左侧选择切换）                         │
│  ──────────  │                                                        │
│  常驻模式    │                                                        │
│  诊断        │                                                        │
│              │                                                        │
├──────────────┴──────────────────────────────────────────────────────┤
│ ● 空闲 · 上次 12 条成功     ~/Downloads/wxdl  [更改]   [恢复网络]     │  底栏：常驻状态条
└─────────────────────────────────────────────────────────────────────┘
```

底栏的「恢复网络」按钮只在代理指向 wxdl 时才可点，其它时候置灰——
**把"系统现在被改过"这件事固定摆在窗口底部，任何页面都看得见。**

菜单栏常驻项（`NSStatusItem`）：只在代理被接管时显示图标，点开是
「常驻中 · 已开启 N 分钟 / 恢复网络 / 打开 wxdl」。用户关了窗口也还能收尾。

**这要求关闭窗口不等于退出 App。** 当前的
`applicationShouldTerminateAfterLastWindowClosed = true`（`gui/WxdlApp.swift:39`）必须改：
只要代理还被接管、或有后台任务，关窗就只隐藏窗口，保留菜单栏图标；
真正退出走 `⌘Q` 或菜单栏，并经过 6.5 的退出拦截。

## 6. 界面详细设计

### 6.1 下载（默认页）

```
┌─ 下载 ─────────────────────────────────────────────────────────────┐
│                                                                      │
│  链接                                                    识别到 3 条 │
│  ┌──────────────────────────────────────────────────────────────┐  │
│  │ https://weixin.qq.com/sph/A2oqg1iKx9                          │  │
│  │ https://weixin.qq.com/sph/ADjOKvyzzI                          │  │
│  │ 看看这条 https://weixin.qq.com/sph/ALIEN2Xrnd 很有意思         │  │
│  │                                                                │  │
│  └──────────────────────────────────────────────────────────────┘  │
│  [ 从剪贴板粘贴 ]  [ 从文件导入 ]  [ 清空 ]      也可以把 .txt 拖进来 │
│                                                                      │
│  待下载 3 条                                          [ 编辑列表 ▾ ] │
│  ┌──────────────────────────────────────────────────────────────┐  │
│  │ ○ 1  https://…/A2oqg1iKx9                                     │  │
│  │ ○ 2  https://…/ADjOKvyzzI                                     │  │
│  │ ○ 3  https://…/ALIEN2Xrnd                     （重复已合并 1 条）│ │
│  └──────────────────────────────────────────────────────────────┘  │
│                                                                      │
│  规格  ( 转码 xWT111 ▾ )     保存到 ~/Downloads/wxdl  [更改…]        │
│                                                                      │
│                                              [ 开始下载  3 条 ]     │
└──────────────────────────────────────────────────────────────────────┘
```

要点：

- **识别结果直接变成可编辑列表**，不再停在"文本框里有多少条"。
  列表里每条可删、可勾选排除；重复合并要给明确说明（"重复已合并 1 条"），
  不能默默少一条。
- **规格改成下拉**，而不是复选框「下载原始视频（不转码）」。
  引擎有多个转码规格（悬停菜单里可选），`--spec` 也接受规格名，
  v1 把它压成一个布尔值，是把能力做窄了。下拉里列出引擎返回的实际规格 + `original`。
  拿不到规格清单时退化为 `默认转码 / 原始视频` 两项，不做自由输入。
- 主按钮文案带数量：**「开始下载 3 条」**，不是「开始下载」。
- 支持把 `.txt` / `.urls` 拖进窗口、拖到 Dock 图标；支持 `⌘V` 粘贴、`⌘⏎` 开始。
- 输入为空时主按钮置灰，右侧显示「还没有链接」。不弹错误横幅——空态不是错误。

### 6.2 准备阶段（阻塞引导）—— 解决卡点 A

下载不是"点了就开始"，中间有一段 wxdl 在装引擎、要授权、等视频号页面。
v1 把这段时间折叠成"进度条在动"。v2 把它做成一个**有步骤、可中断、会自己继续**的面板，
替换掉那句 9 秒消失的横幅。

```
┌─ 正在准备 ─────────────────────────────────────────────────────────┐
│                                                                      │
│  ✓ 环境检查          微信已运行 · Wi-Fi · 引擎 v260907               │
│  ✓ 管理员授权        已信任根证书，代理已指向 127.0.0.1:2023          │
│  ✓ 抓取引擎          已启动                                          │
│  ● 微信视频号页面    未连接                              [ 怎么弄？] │
│  ○ 开始下载          等待中                                          │
│                                                                      │
│  ┌──────────────────────────────────────────────────────────────┐  │
│  │ 微信需要重启一次，它现在还在用旧的代理设置。                     │  │
│  │                                                                │  │
│  │  1. 回到微信，按 ⌘Q 完全退出（不是关窗口）                      │  │
│  │  2. 重新打开微信，进入「视频号」                                │  │
│  │  3. 点开任意一条视频，让页面停在那儿                            │  │
│  │                                                                │  │
│  │  完成后这里会自动继续，不用再点什么。          [ 重新检测 ]      │  │
│  └──────────────────────────────────────────────────────────────┘  │
│                                                                      │
│  已等待 00:42                                                     │
│                                          [ 停止并恢复网络 ]         │
└──────────────────────────────────────────────────────────────────────┘
```

设计决定：

- **四步固定可见**，完成打勾、当前高亮、未开始灰字。用户随时知道卡在第几步。
- **等待页面连接这一步不静默超时。** GUI 给 `wxdl` 传 `--wait-page=forever`，
  倒计时只显示已等待时间，不判失败；页面连上后 `wait.page` 事件带 `connected:true`，面板自动继续。
  只有用户主动点「停止并恢复网络」才结束（此时必须恢复代理，这是唯一收尾路径）。
  普通 CLI 不传这个参数，仍是 Prepare 2 分钟、批量掉线每条 3 分 45 秒，行为不变。
- 「怎么弄？」展开的是上面那段三步说明，配一张微信界面的截图，不写长文。
- 这一步**只在前置条件不满足时出现**。第二次以后证书已信任、引擎已装，
  四步一闪而过，不阻塞。

### 6.3 任务列表（下载中）

```
┌─ 正在下载 3 条 ─────────────────────────────── 2/3 · 剩余约 4 分钟 ─┐
│                                                                      │
│  ▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓░░░░░░░░░░░░░░░░  64%                            │
│                                                                      │
│  ✓ 老王的线下派对 #人生价值 …            28.8 MB · 2:58              │
│  ⋯ 述职大会，我坚持要开下去 …            12.1 / 28.8 MB · 1.2 MB/s   │
│     ▓▓▓▓▓▓▓▓░░░░░░░░░  42%                                          │
│  ⤼ 辨别假酒：…                            之前下过了                │
│  ○ 排队中                                                           │
│                                                                      │
│  ──────────────────────────────────────────────────────────────────  │
│                                            [ 停止 ]  [ 后台继续 ]   │
└──────────────────────────────────────────────────────────────────────┘
```

要点：

- **单条有字节进度和速度**（来自 `item.progress`）。这是 v2 相对 v1 最直观的体验提升。
- 三种终态用三种符号：`✓` 成功、`⤼` 跳过（灰色，副标题写「之前下过了」，**不标红**）、
  `✕` 失败（红色 + 一句话原因 + 「重试这条」）。
- 「剩余约 N 分钟」只在完成 ≥2 条后才显示，用已完成条目的平均耗时推算。
  第一批就显示预估是瞎猜，宁可不显示。
- 「后台继续」：隐藏窗口、菜单栏图标接管、跑完发系统通知。
  下 50 条要十几分钟，用户会切走，必须有这个出口。
- 列表用 `LazyVStack`/`List`，不用 `ForEach` 全量渲染；日志同理，见 6.6。

关键改动：**先搜索再选，不直接拿关键词去下。**

  第一次搜索会走 6.2 的准备流程（可能弹一次管理员密码），设计上把搜索放进同一个

  （这是 CLI 已有的定位方式，要告诉用户。）

### 6.5 常驻模式

```
┌─ 常驻模式 ─────────────────────────────────────────────────────────┐
│                                                                      │
│  开启后，微信视频号窗口里会出现「下载」按钮：                        │
│  视频详情页底部一个悬浮按钮，首页右侧一个图标，鼠标悬停可以选         │
│  「原始视频」和各清晰度。下到的文件和「下载」页是同一个目录。         │
│                                                                      │
│  ┌──────────────────────────────────────────────────────────────┐  │
│  │  状态   已开启 · 12 分钟                                       │  │
│  │  代理   127.0.0.1:2023（已接管系统代理）                       │  │
│  │  引擎   v260907 运行中                                         │  │
│  └──────────────────────────────────────────────────────────────┘  │
│                                                                      │
│  关闭 wxdl 不会自动恢复网络——代理会一直留着，直到你点「停止」。      │
│                                                                      │
│                              [ 停止并恢复网络 ]   [ 打开微信 ]      │
└──────────────────────────────────────────────────────────────────────┘
```

配套的三种兜底，缺一不可：

1. **底栏常驻状态条**（第 5 节），任何页面都看得到。
2. **菜单栏图标**：只在开启时出现，点开可直接「恢复网络」。
   这要求关窗不退出 App（见第 5 节），否则图标会跟着 App 一起消失。
3. **退出拦截**：代理仍被接管时 `⌘Q` 或关窗，弹确认
   「系统代理还指向 wxdl。退出前要恢复吗？」→ `恢复并退出` / `保持代理并退出` / `取消`。
   选"保持"会**保留菜单栏图标**（如果用户选择退出 App，则明确告知需要重新打开 wxdl 或运行
   `wxdl off` 收尾）。**不允许静默退出。**

另外：常驻模式开着时从 GUI 发起下载，必须带 `--keep`（或等价语义），
否则 `wxdl get` 跑完会把常驻一起收掉（README「常驻模式下命令行请用 --keep」）。
设计上默认做"检测到代理已指向 wxdl 就自动保持"，下完底栏继续保持「常驻中」；
用户要结束常驻，走「停止并恢复网络」。

### 6.6 诊断（原「自检」升级）

把 `wxdl doctor` 的 `flow.Check` 列表逐项渲染，每项右侧给修复动作：

| 项 | 状态 | 说明 | 动作 |
|---|---|---|---|
| 微信客户端 | ✓ | 正在运行 | — |
| 网络服务 | ✓ | Wi-Fi | — |
| 系统代理 | ! | `socksfirewall=127.0.0.1:7897` | 打开网络设置 |
| 代理冲突 | ✕ | Clash | 退出 Clash |
| 抓取引擎 | ✓ | v260907 | 重新安装 |
| ffprobe | ! | 未安装（可选） | — |

**注意**：系统代理指向别的程序（例如 Clash）时，不要给「恢复网络」按钮。
`wxdl undo` 只回滚 wxdl 自己保存的快照；没有快照时 `proxy.Restore` 直接返回
（`internal/proxy/proxy.go:208`），点了不会有任何效果。这里只能引导用户退出冲突程序
或打开系统网络设置。

「退出 Clash」点下去是引导（打开该应用并提示 ⌘Q），不替用户强杀进程——
README 已经写明"不会替你退出"，这个克制要保留。

日志区改造：默认折叠进诊断页，**默认显示"用户时间线"**（成功/失败/跳过各一行），
「查看原始日志」才展开 monospace 全文，并提供「导出到文件」。
理由：12 万字符的 monospace 日志对开发者有用，对目标用户是噪音。
同时把 v1 那个单 `Text` 换成 `List` + 环形缓冲（内存上限 2000 行），解决长批次卡顿。

### 6.7 已下载（新增页）

下载完必须跳 Finder 才能看到结果，是最后一段没接上的路。

- 读 `~/Downloads/wxdl`（跟随设置里的目录），按修改时间倒序列表：
  缩略图（用 `QLThumbnailGenerator`，不依赖 ffprobe）、标题、大小、时长、规格。
- 支持 Quick Look（空格）、双击用默认播放器打开、「在访达中显示」。
- 顶部一个「本次下载 12 条」过滤，方便刚下完的人只看新的。
- 不做：批量改名、转码、打标签、去重清理。这些是另一个产品的活。

## 7. 状态机

### 7.1 任务（单条）

```
queued ──▶ running ──▶ done
              │  ├──▶ skipped (already_downloaded)
              │  └──▶ failed ──▶ (重试) ──▶ queued
              └──▶ cancelled
```

`skipped` 是终态且**计入成功**，UI 用灰色 `⤼`。

### 7.2 会话（全局）

```
idle ─▶ checking ─▶ authorizing ─▶ installing ─▶ waiting_page ─▶ downloading ─▶ finishing ─▶ idle
  │         │            │                            │                │              │
  │         └── 缺失/冲突 ─▶ blocked（诊断页 + 修复动作）   │                │              │
  │                                                      └── 用户停止 ─┴──▶ finishing     │
  └──────────────────────── resident（常驻模式，独立于 idle）◀───────────────────────────────┘
```

`waiting_page` 在 GUI 下不设上限（`--wait-page=forever`），只由用户停止；
普通 CLI 仍有超时。`finishing` 是必须显式呈现的阶段：停止引擎 + 恢复代理，
最长十几秒（v1 里硬编码 12/15 秒）。v2 在这个阶段显示「正在恢复网络设置…」，
并**禁止再次点击任何主按钮**。
`resident` 与 `idle` 是正交的：App 可以"空闲但同时处于常驻模式"，底栏要能同时表达这两件事。

## 8. 视觉规范

目标：**看起来像一个正经的 macOS 小工具**（参考活动监视器、Sourdough、Finder 的信息密度），
不是一个网页套壳。

**必须遵守：**

- 全部使用系统控件与 `SF Symbols`；不自制进度条、复选框、开关。
- 强调色用系统 `accentColor`（跟随用户在系统设置里的选择），不硬编码蓝/紫。
- 语义色只用系统 `.red / .orange / .green`，且**只用于语义**（失败/警告/成功），不做装饰。
- 圆角：卡片 6pt，控件 4pt，窗口按系统。不用 12pt 以上的大圆角。
- 字号：正文 13pt / 次要 11pt / 日志与表格 10pt；行高 1.4；数字用 `monospacedDigit()`。
- 间距栅格 4pt，卡片内边距 14pt，卡片间距 12pt。
- 深浅色都走系统语义色（`windowBackgroundColor` / `controlBackgroundColor` /
  `labelColor` / `secondaryLabelColor`），不写死 hex，深色模式自动跟随。

**明确不做：**

- 不用 emoji 当图标或分隔符。
- 不用渐变背景、玻璃拟态、发光按钮、卡片阴影堆叠。
- 不做营销式空态插画和吉祥物。
- 不做启动闪屏、"欢迎使用"引导页。首次要说的东西放第 6.2 节的准备面板里，
  那里才是真正需要它的时机。
- 图标沿用现有 App 图标（紫色 app icon 已随包发布），界面内不额外铺品牌色。

## 9. 文案与错误规范

原则：**一句话说清发生了什么 + 一个动作按钮。** 不写"出错了，请重试"。

| code | 界面文案 | 主按钮 | 次按钮 |
|---|---|---|---|
| `page_not_connected` | 微信里的视频号页面还没连上 | 打开微信 | 查看做法 |
| `wechat_not_running` | 微信没在运行，先打开并登录 | 打开微信 | — |
| `proxy_conflict` | Clash 正在占用系统代理，抓不到视频号流量 | 退出 Clash | 仍然继续 |
| `auth_cancelled` | 你取消了授权，没有改动任何设置 | 重新授权 | — |
| `lock_held` | 另一个 wxdl 正在下载，等它结束 | 查看那个任务 | — |
| `engine_missing` | 抓取引擎没装好 | 重新安装 | — |
| `engine_install_failed` | 抓取引擎没能装好 | 重试 | 查看日志 |
| `port_in_use` | 2023 端口被别的程序占了 | 查看是谁 | — |
| `network_unavailable` | 没有识别到可用的网络连接 | 打开网络设置 | — |
| `timeout` | 这条等太久了 | 重试这条 | 跳过 |
| `disk_full` | 磁盘空间不够了 | 打开下载目录 | 换个位置 |
| `network_lost` | 下载中断网了 | 重试失败的 N 条 | — |
| `download_failed` | 这条没有下载成功 | 重试这条 | 查看日志 |
| `restore_failed` | 停止时没能恢复系统代理，网络可能还不通 | 打开网络设置 | 再试一次 |

通用要求：

- 错误里**不要出现路径、退出码、Go 的 error 字符串原文**。
  那些进"查看原始日志"。
- 原来的「强制解锁」不再提供：文件锁是 `flock`，进程退出会自动释放；
  真要"强制"只剩杀掉另一个正在下载的进程，风险大于收益。
- 成功不弹窗，走底栏一行字 + （后台时）系统通知。

## 10. 无障碍与细节

- 所有图标按钮带 `help()` / accessibility label；状态变化对 VoiceOver 播报一次。
- 颜色不单独承载信息：成功/失败/跳过必须同时有符号和文字。
- 窗口最小尺寸 900×640，侧栏可折叠；内容区支持缩放（`⌘+`/`⌘-` 走系统文本大小设置）。
- 快捷键：`⌘V` 粘贴、`⌘⏎` 开始、`⌘.` 停止、`⌘1..5` 切页、`⌘L` 显示日志、`⌘,` 设置。
- 剪贴板：**不自动监听**。只提供「从剪贴板粘贴」按钮和首次进入时的一个"剪贴板里有 N 条链接，要粘贴吗？"提示。
  静默轮询剪贴板对一个需要系统代理权限的工具来说不合适。

## 12. 风险与未决问题

1. **（已关闭）字节进度能不能拿到。** `下载 16% (4.7MB/28.8MB)` 是 wxdl 自己从
   `TaskDetail.Files[].Downloaded/Size` 算出来的，不是引擎 stdout；P0 直接在 `waitTask`
   里发 `item.progress` 即可，不需要改上游引擎。只有 `File.Size` 尚未就绪时才退回不确定态。
2. **`wxdl accounts` 能不能实现。** 搜索 API 已存在（`flow.go:215`），命令本身可行；
   真正未验证的是头像 URL、视频数等展示字段。拿不到就退化为"昵称 + username"列表。
   更麻烦的是 prepare 生命周期：搜索需要引擎+代理+证书+页面，必须和下载共用一次
   capture session，否则会连续两次授权。这个要在 P2 前定方案。
3. **规格列表从哪来。** 6.1 的下拉需要引擎返回可用规格清单；若拿不到，
   退化为 `默认转码 / 原始视频` 两项，不做自由输入。上游支持 `video_variant_key`，
   但 wxdl 还没有取规格列表的 API。
4. **macOS 26 的视觉变更。** 工具栏与侧栏在新系统上有新规范，需真机确认；
   最低支持版本维持 12，不因适配上抬；侧栏实现不能依赖 13+ 的 `NavigationSplitView`。
5. **签名缺失。** 现包没有 Apple 开发者签名，首次打开要右键绕过。
   这与 GUI 无关但直接影响"完全不用终端"这个目标——
   README 里给的 `xattr` 命令就是终端。需要在安装引导里内置一个「若打不开点这里」
   的自检与说明，或者评估 Notarize 的成本。P1 的验收要注明"已右键打开"前提。
6. **没有真机 Intel 验证。** 现 Intel 包只在 Rosetta 下启动过。GUI 改动后同样如此，
   文档与 Release 说明里继续如实标注，不声称已验证。
7. **（已处理，P1 仍需界面）常驻与下载的生命周期。** `wxdl get` 不带 `--keep` 会收掉常驻
   （README:365）。GUI 现在检测到 `proxy_is_ours` 就自动带 `--keep`，不会"下完一批常驻突然没了"；
   但底栏状态条与一键恢复网络仍属于 P1。
8. **关窗策略。** 菜单栏图标和"后台继续"都要求关窗不退出 App。
   需要同时处理 `⌘Q`、关窗、Dock 退出三条路径，避免出现"App 已退出但代理还在"。
